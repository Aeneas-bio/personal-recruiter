## Contribution review process

Every pull request, from internal or external contributors, requires explicit approval from a repository admin before it is merged. This is enforced via required reviews and the `CODEOWNERS` file — no pull request merges without sign-off from one of the admins listed there. An admin's approval is not automatic and reflects a judgment call on fit, quality, and licensing implications, not just a rubber stamp on passing checks.

## Before you open a pull request

- Check existing issues and pull requests to avoid duplicate work.
- Keep changes focused — a pull request that mixes an unrelated refactor with the fix or feature it's meant to deliver is harder to review and slower to approve.
- Describe what changed and why in the pull request body.
